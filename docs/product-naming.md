# Arbiter Product Naming Guidance

Use public-safe product vocabulary in organization profile content, public docs, issue titles, PR summaries, demos, and UI labels.

## Public authority

For public MVP feature names and claim guardrails, use [Public MVP Feature Language](product/public-mvp-feature-language.md) as the authoritative public-safe source.

This document provides general naming principles. It does not override the public MVP feature-language guide, create runtime scope, define GitHub Project fields, or expand acceptance criteria.

## Public guidance

- Use names that describe user-visible outcomes.
- Keep product names aligned with implemented or explicitly planned public-safe behavior.
- Avoid implying production readiness, compliance certification, billing-grade reporting, guaranteed savings, customer deployment, or self-serve availability unless those claims are approved and currently true.
- Keep public examples synthetic and safe.
- Do not expose private naming documents, roadmap notes, competitive strategy, customer details, implementation sequencing, or internal planning records.

## Current public positioning

Arbiter Systems builds infrastructure for controlled, observable, reliable AI execution.
